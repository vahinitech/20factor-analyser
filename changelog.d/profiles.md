- School, class and child profiles, as data on top of the language packs (docs/20-languages.md section 18.1, #220). `backend/languages/profile.schema.json` and `profile.py` apply the layers school, then class, then child, each field with an explicit `set`, `add` or `remove`: the letter model and accepted letter forms (only from the pack's reviewed lists, which are empty for Latin until a teacher reviews them), the ruling, class word lists, exception words, what to skip and which language-skill checks run. Fixed fields and literal words only, with no code and no patterns, and a size limit on every list and on the whole profile. There is no field for health, diagnosis, ability or a child's name outside the exception words.
- `/api/v2/reports` and `/report-python` take an optional `profile` form field with the profile as JSON text. Nothing is stored, logged or sent to analytics, since exception lists can hold children's names; who may keep profiles waits for the owner. A refused profile gets HTTP 413 or 422 with a `profile_*` error code before the photo is read, and does not count as a free check.
- Reports carry `ruleset`, the hash of the language pack and the resolved profile, and so does `comparability`; the cache keys on it too. Without a profile the hash is the pack's own and every score is unchanged. A letter whose accepted forms are set to an empty list is not taught yet; when every letter factor 3 (loops and bowls) or factor 6 (tall letters) counts is untaught, that factor is "Not measured" with the profile's reason, never a higher score. Exception words, skip rules, word lists and checks are resolved, checked and hashed only, until the script decision (#211) and the language skills (#221) read them.
