- A photo the browser cannot open no longer does nothing. On 2026-10-06 a visitor on Chrome for Mac, between JPEG uploads that worked (the first got a printed report), tried one iPhone HEIC photo five times: each time no preview, no message, "Run analysis" greyed out, and a rejected upload in the store. Chrome and Firefox now convert a HEIC photo to JPEG in the browser with libheif (libheif-js 1.23.5, LGPL-3.0), loaded from jsDelivr only for such a photo: about 520 KB compressed, the script pinned by SRI and the wasm file by SHA-384. If a photo still cannot be opened, a notice in the upload box says so; for HEIC it gives the ways to get a JPEG (Preview on a Mac, Most Compatible on an iPhone). The page reports that outcome (`heic` or `unreadable`) to vahinitech.com's weekly report. Photos are never stored (owner decision, 2026-10-09): the page no longer sends the photo to vahinitech.com's upload store, only a record that one was checked (type, extension, size, page, consent; no file name), and a printed report is stored as its scores and quality facts only (no report text, HTML, name, email, URL or browser details). The "What happens to my photo?" answer says so. `tests/unreadable-image.mjs` (`npm run test:unreadable`) covers it with a real HEIC fixture, and checks that no record carries image data or a file name.
- Upload limits fit one page. The API now takes at most 5 MiB per file and 6 MiB per request (was 30 and 32 MiB), refused before anything is decoded; the website sends at most 2600 px and the Android app 2200 px, both as JPEG, and the largest of 127 real uploads came to 1.8 MB as sent (2026-10-09). The upload box refuses a picked file over 10 MB (was a 25 MB hint with no check) with a notice saying what to do, and reports the outcome as `too_big`. `report-request.schema.json` and API-V2.md say so; the Umbrella contracts copy needs the same sync after merge.
