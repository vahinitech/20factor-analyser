- Comparing two checks is now enforced by the server: `POST /api/v2/compare` takes a Pro key and two receipts, answers 403 without Pro, and returns both stored records with the comparability notes (dates the wrong way round or on one day, different scripts, word counts more than 25% apart, printed text on one page). Each receipt now has a read-only token, which the shared PDF carries instead of the full one: it opens a record only through the comparison and cannot read alone, renew or delete. The full token stays in the browser's saved checks. `backend/report_store.py`, `backend/ppocr-server.py`, `backend/schemas/compare*.schema.json`, `frontend/src/report/report-share.js`.
