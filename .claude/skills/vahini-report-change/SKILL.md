Read [CLAUDE.md](../../../CLAUDE.md) and the relevant sections of [report contract guidance](../../../docs/12-report-rules.md). Consult [API-V2.md](../../../backend/API-V2.md) for request/response details and [skills.md](../../../skills.md) for prose.

Before editing any report file, read the [report format baseline](../../../docs/12-report-rules.md#report-format-baseline-owner-approval-required). The owner (@vkosuri) approves every change to the report's page structure, sections, styling or per-tier rendering. If the task needs one, stop and ask with before and after screenshots; do not make it and explain afterwards. Bug fixes that keep the rendered format need no approval.

Personal data (owner, 2026-10-31): a change to uploads and the check (`backend/server/app.py`, `upload_limits.py`, `daily_limit.py`), the report store (`backend/server/report_store.py`), the debug store (`debug_store.py`), access and subscriptions (`access_api.py`, `entitlements.py`, `subscription_admin.py`), the age band (`age_band.py`), the words read from a page and anything in the report text that could name a person, and the check page, print popup and share in `frontend/src/app/` runs the [DPDP check](../dpdp-check/SKILL.md) first. Photos and report text are never stored; the report store keeps only its allowlist; children read and are checked here, so Section 9 and Rule 10 apply to every check. A change that may break a rule stops for the owner's decision before it is committed.

Brand colours, type and ink come from the Vahini design system: pages link `/site/design/v1/vahini.css` (served by vahinitech.com) and CSS uses `var(--v-*)` tokens with no fallbacks and no brand colour codes. The redesigned report (version C, 2026-10-11: page 1, the practice sheet, the side panel and the shared PDF) follows this website theme. Only the report's own colours (score bands, paper, rules) stay in `report.css`; vahini-web's `input-manifest.yaml` caps how many colour literals each stylesheet may hold.

The Free report shows all five Free factors on page 1 as chips, the photo zoomed to the parts it looks at with numbered boxes, and two rows with crops from the visitor's uploaded photo (version C, owner approval 2026-10-11). The server sends Free the `evidence` regions of those five factors only; never show a locked factor's crop, a stock example in place of a missing crop, or a crop from any photo but the visitor's.

Scan work runs through `scan_slots.slot()` and `scan_slots.run()` (capacity sized by `backend/server/capacity.py`, see #97); a new endpoint that decodes or scans must use them too. After any change under `frontend/src`, run `python frontend/build_bundle.py`: it rebuilds the bundle and the `?v=` stamps that keep Cloudflare from serving old scripts with a new page. Regenerate the sample report with `docs/examples/generate_photo_sample.py`, not by hand.

Keep authorization server-owned, preserve the existing expanded contract, and update dictionary versions and the browser adapter together when their contract changes. Rebuild the frontend bundle after source edits. Verify returned values and actual printable output rather than only screenshots or fixture counts.

Printable output means the page count, not only each sheet's height. The free report is two A4 sheets; `tests/report-layout.mjs` prints the PDF and fails on any other count, once with the fixture and once with sheets stretched to the length a real photo produces (the fixture's text is shorter, which is how 3-4 page prints with blank pages passed every check on 2026-10-07). Any change to report content, spacing or `fitPrintPages()` reruns it; when real content grows, update the stretched heights from a real print, not from the fixture.

Uploads and decoding follow [SECURITY.md](../../../SECURITY.md#upload-and-image-security-rules-for-every-change): a new endpoint that takes a file uses `_read_upload` (5 MiB), `computer_vision.decode_image` (24 MP, JPEG/PNG/WebP/PDF only), `scan_slots` and `daily_limit.DAILY`, and writes nothing to disk. The container runs as user 10001 on a read-only filesystem; anything it must write goes to `/tmp` or a volume.

Practice cards follow [10-practice-framework.md](../../../docs/10-practice-framework.md): a development area per factor links its exercises, tips, worksheet and translations; the band sets how much, the tier sets how many. A card always says which page-1 skill it develops and its score. New exercises and tips go into the catalogue with tests, never into `report-render.js`. Translated report text needs a native speaker's check before its language is offered, and printing in that language must still give two A4 sheets with the script's font embedded.

Children read the report. Every sentence encourages (10-practice-framework.md, "Words for children"): open with a strength, say "skills to grow" and "your next step", describe the writing rather than the child, and never use "weak", "poor", "bad", "wrong", "problem", "inadequate", "fail" or "lowest". Only the skills the report flags get exercises and tips; Free shows one of each per skill, and the per-tier numbers come from the server's access answer, not from the page.

For PR review, use [review instructions](../../../.github/instructions/code-review.instructions.md). Use synthetic samples and test credentials. Do not claim native app changes or store purchase verification from backend work. The consuming website owns its staging and production deployment workflow.

**Resolve comments and conflicts first, then merge (owner, 2026-10-14).** Before merging a pull request: answer every review comment and code-scanning alert on it, by fixing the code or replying why not, and resolve each thread; a bot's comment (CodeQL, Copilot) counts like a person's. Bring the branch up to date with `main` and resolve any merge conflict. Then wait for CI on that final commit to pass, and only then merge. Check with `gh pr view <n> --json mergeable` (must be `MERGEABLE`) and `gh api graphql -f query='{repository(owner:"vahinitech",name:"<repo>"){pullRequest(number:<n>){reviewThreads(first:100){nodes{isResolved}}}}}'` (every `isResolved` true). #150 merged with two CodeQL threads still showing open; the code was fixed, but nobody could tell from the PR.

Test payloads for uploads (fake PHP, web shells, EICAR) are joined from parts at run time and never named like a web shell: the server's maldet scan flags the whole string in any file, and `backend/tests/test_scanner_strings.py` fails on it. See CLAUDE.md, "Never write a malware-scanner string in one piece".
